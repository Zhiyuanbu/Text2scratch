1. Quick start

Use this sequence when you are building a new project

It prevents most of the errors new users hit on their first export.

  1. Open the converter and start with project setup commands such as make_var, make_list, and make_broadcast.
  2. Write stage logic under stage_code =.
  3. Declare each sprite with sprite = "Name", then add its code block with name_code =.
  4. Read compiler output before exporting. Fix structure issues first, then content issues.
  5. Export .sb3 for Scratch or .t2sh for a session backup.
make_var score 0
make_broadcast start_round

stage_code =
  when_flag_clicked
  set_var score 0
  broadcast start_round
end

sprite = "Cat"
cat_code =
  when_broadcast_received start_round
  repeat 5
    move 12
    change_var score 1
  end
end

2. Syntax rules

The rules that matter most

If you remember these, you avoid most parser failures.

One command per line

Do not chain multiple commands together. Write each action on its own line.

move 10
turn_right 15

Indent nested bodies

Nested commands should be indented for clarity. The parser mainly relies on structure and end, but indentation keeps the file readable.

repeat 10
  move 10
end

Close control blocks with end

Blocks such as repeat, if, if_else, and forever must be closed.

if @gt(@var(score), 5)
  say "Win"
end

Quote text with spaces

Wrap string values in double quotes when they contain spaces or punctuation that should stay together.

say "Level complete"

3. Project structure

Think in setup, stage, and sprite sections

text2scratch is easiest to reason about when the file follows a predictable layout.

Setup section

Declare variables, lists, broadcasts, and any top-level configuration before you start scripts.

  • make_var score 0
  • make_list inventory
  • make_broadcast start_round

Stage section

Use exactly stage_code = for stage logic. Stage scripts should not contain sprite-only blocks like movement or costume changes.

Sprite section

Each sprite starts with sprite = "Name". The matching code section uses the lower-case sprite name plus _code =.

sprite = "Ball"
ball_code =
  when_flag_clicked
  go_to_xy 0 0
end

4. Expressions and @ syntax

Use @ when a command should return a value instead of acting like a line on its own

This is one of the biggest conceptual differences for new users.

Correct

set_var score @add(@var(score), 1)
if @gt(@var(score), 5)
  say "Ready"
end

Incorrect

@add(1,2)
@var(score)
  • Reporter and boolean commands usually start with @.
  • They belong inside another command input, not as standalone lines.
  • If you want exact reporter and boolean syntax, use the reference page or the plain /dev route.

5. Stage and sprite rules

Target compatibility matters

Some commands only make sense on sprites, and the compiler will warn when they appear in stage code.

Sprite-only examples

  • move
  • turn_right
  • show and hide
  • next_costume

Safe stage examples

  • when_flag_clicked
  • broadcast
  • switch_backdrop_to
  • Variable and list setup commands

6. Import, export, and share

Choose the right output for the job

.sb3

The standard Scratch project file. Export this when you want to open the result in Scratch.

.t2sh

A text2scratch session archive. Use this for fast restore, backups, or version snapshots of your working text.

Cloud save and sharing

Accounts are optional. When signed in, you can save projects, load them later, and generate read-only share links for others.

7. Debugging guide

What to check when the compiler complains

Missing end

If export is blocked, count your open control blocks first. Nested structures are the most common failure point.

Unknown command

Open the reference page and search the command name. Aliases exist for some commands, but not every natural-language variation is supported.

Expression used as a line

Reporter and boolean expressions should be embedded into another command input instead of written as their own lines.

Stage or sprite mismatch

If a command targets the wrong object type, move it to the appropriate section or switch to a compatible command.

8. Example

A complete starter file you can paste into the workspace

make_var score 0
make_broadcast round_start

stage_code =
  when_flag_clicked
  switch_backdrop_to backdrop1
  set_var score 0
  broadcast round_start
end

sprite = "Cat"
cat_code =
  when_broadcast_received round_start
  repeat 8
    move 10
    turn_right 20
    change_var score 1
  end
end

sprite = "Ball"
ball_code =
  when_broadcast_received round_start
  go_to_xy 0 0
  if @gt(@var(score), 5)
    say "Game on"
  else
    think "Need more points"
  end
end
